# 参考驱动的 Blender 场景制作

这是流程协调层。使用当前环境已有的 Blender 单位/场景、硬表面、材质、UV、贴图、灯光、渲染、优化、QA 和导出能力执行专业工作；图纸尺度校核时就介入，不能到最后只列技能名称。详细尺寸规则见 [尺度与资产约定](references/scale-and-review.md)。

## 1. 明确任务与来源

先读取项目约定和已有资产，区分分析、参考、单件和整景任务。记录目标引擎、实际相机和分辨率、角色可见身高、移动层和落地面、需要保留的工程行为。

生成前分别确认本任务图片和建模脚本使用当前 Codex 还是用户自配 API；继承同任务已明确的选择，无须逐图询问。可以混合路线。仅复用旧成果时不需要新选择；路线不可用时不静默切换。

API 路线生成的是图片或建模脚本，几何仍在本地 Blender 执行。只有一个调度者使用原客户端及共享请求状态提交/恢复；不向建筑 agent 分发密钥，不创建新账本绕过待处理请求，不默认付费重试。费用或额度错误、请求结果不明时遵循用户当前授权与客户端恢复规则。

## 2. 拆解并建立尺度基准

按地面、重点建筑、可复用立面、店面、标牌、道具、植物、远景拆解，优先决定风格的代表资产。给每件资产分配 ID、独立文件范围、主要识别特征及几何/纹理/碰撞职责。使用 [资产卡](assets/asset-card.json)，示例与空字段不代表批准。

两栋及以上不同建筑：一栋一个独立 subagent，共享角色、街面、单位与接口约定，在可用槽位内并行或分波次推进。主 agent 负责路线、参考汇总、API 调度和组装。单件不强制拆 agent，已批准模型的实例复制不要求逐实例分派。环境不支持委派时说明限制，不能声称已并行执行。

## 3. 先出图并修订尺度

每件独立建模资产提供同一设计版本的透视参考、正面、侧面和俯视图；从属小件可包含在所属资产图组中。保留已有认可概念，不无故重新设计。新增背面或局部图只用于解决实际结构歧义。

以共同单位、比例、落地线和关键尺寸制作三视图，检查开口数量、楼层、附件、屋顶位置一致。AI 视图不是测量真值；冲突按用户要求、可信参考、常规尺度和明确估计处理，记录修订依据。

设计完成后结合 Blender 场景/尺度和硬表面规则核对普通门、店口、展示窗、层高、台阶与家具用途。提供同尺度角色对照及门洞/门扇/净通行尺寸，修图后再提交。

提交可查看的图组，标注资产 ID、版本、尺寸与未决假设。等待用户确认该版本后才创建目标几何、粗模或生成建模脚本（含 API 请求）。不能先做模型再渲染来绕过参考确认。选择 API、沉默、超时、机器 QA 或批准整体风格都不等于批准各件图纸。

记录批准的资产 ID、版本和范围。明确批准整批可放行整批，部分批准只放行对应资产。用户明确豁免该阶段时记录其范围；未变的已批准设计可复用。实质改变轮廓、尺寸、开口或主要材质分区需更新受影响图组；忠实实施已批准设计的技术修复不再询问。

## 4. 建模与材质

将批准版本、组件用途、尺寸、角色基准和设计例外传给脚本生成者。审查 API 代码的文件、进程、网络和删除操作后执行，保留原始返回与本地修改来源。

本地 Blender 以米制制作粗模，先轮廓、退进、开口和承重连接。测实际尺寸，正交检查后再看真实游戏相机；别用缩放角色、改变镜头或增加灯光掩盖比例问题。

轮廓、投影和明确厚度使用几何；砖纹、微小磨损及适合的远景使用纹理/视差。材质记录物理重复尺度，分开 Base Color、Roughness、Normal 和 Emission；不把参考中固定高光和阴影直接当颜色贴图。磨损按结构分布，避免全墙均匀噪声。

先验证一个模块再实例化。各 agent 只写自己的文件；组装时不拉伸已验证的门窗来填缝。按最终镜头分配细节与预算，不套用统一面数。

## 5. 引擎样板与交付

先用一件代表建筑、真实角色、地面和基本背景形成引擎样板。中性光检查结构/材质后再调氛围；在目标分辨率下检查轮廓、开口、店铺身份、明暗、人物可读性及遮挡。Blender 展示渲染不能替代实际引擎截图。

每轮处理最明显的少数差异。已批准范围内正常迭代不要求逐步批准；用户明确要求审核样板时才等待。通过一个样板不自动批准其他未确认资产。

组装后按受影响范围完成几何 QA、多角度材质及线框检查、导出回读、纹理依赖和实际引擎检查；必要时验证碰撞、双向通行、镜头、剔除与暂停。修复技术错误；保留警告需有证据、原因和适用限制。不要扩大容差或隐藏报告来宣称通过，也不要用检查数量替代外观判断。

交付可编辑源文件、引擎格式、纹理、资产卡、实际截图与简短记录。分别报告设计尺度、图纸/模型一致性、技术状态、游戏视觉判断、用户认可状态。只改一件就重建和核查受影响部分。

原图和模型留本地，日常展示小预览；需要看精细缺陷时补无损局部。将阶段结果与批准状态写入交接记录，避免长对话重复传输整套高清图片。
