# 尺度与资产约定

## 坐标与依据

在资产卡明确单位、轴向、朝向、原点、落地面、连接点。记录尺寸来源属于用户要求、可信测量、常规参考还是设计估计。所有视图共享一套尺寸基准，不独立缩放至铺满画布。

常见成人门高约 2.0–2.1m、宽约 0.9m，可作普通游戏资产的初步标尺；不适用于所有门型，也不是建筑法规。特殊用途与风格化尺寸需要具体理由。最终以本任务获批尺寸为准，不通过改容差掩盖偏差。

## 重点比例

- 门：门洞、可见门扇、净通行口、门框、门槛与上亮窗分别记录。宽高比应针对实际可见门扇，不能拿整套装饰外框替代。
- 楼层：层高、楼板厚度和净高分开。楼层变高不意味着门把手和柜台等一起同比放大。
- 人物：测可见头顶到足底，排除透明画布、伞、烟雾和武器；碰撞体高度另记。五头身是造型比例，不是自动缩小建筑的倍率。
- 透视：图纸放同尺度人形；模型检查将角色与门置于同深度，或明确校正透视。角色靠前、建筑靠后会影响画面中的高度比。
- 设施：按用途检查栏杆、台阶、桌椅、柜台和通道净宽，仅填写本资产涉及的对象。

## 分开回答五个问题

1. 设计尺度有没有依据，功能是否合理？
2. 实际模型有没有忠实实现获批图纸？
3. 几何、材质和导出是否技术合格？
4. 实际游戏镜头里是否符合目标风格？
5. 用户是否认可最终外观？

同一组错误尺寸可以同时通过图纸/模型一致性检查，因此第 2 项不能替代第 1 项。零技术错误不能替代第 4、5 项。

## 批量交接

主 agent 提供统一角色尺度、地面标高、坐标约定、风格、路线和预算。负责人只写独占目录，回交资产 ID、图组版本、尺寸、设计例外与检查记录。

确认前的 agent 只能准备参考和二维尺度修订；确认后才接收建模任务。API 调度者持有请求状态，负责人不接触密钥，也不为失败自行发起收费重试。

## 状态记录

`planned → reference_drafted → proportions_reviewed → awaiting_reference_approval → reference_approved → blockout_checked → detail_checked → engine_checked`

`proportions_reviewed` 仍不允许建模。参考批准、技术检查、最终视觉认可使用不同字段。已批准资产仅有技术修复或文件迁移时，无须机械重走设计批准；实质设计变更只让受影响资产返回参考阶段。
